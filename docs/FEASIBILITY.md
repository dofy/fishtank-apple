# macOS + iPadOS 改造可行性

评估日期：2026-10-20。源项目当前 package.json 为 1.8.0，基于提交 `5eb7520` 的本地源码评估，不据此推断线上发布状态。

## 结论

可行，建议采用 **SwiftUI + SpriteKit + 独立 Swift 玩法核心**，macOS 加菜单栏入口，iPadOS 提供完整游戏界面。新项目已经建立两个应用目标用于验证。主要工作量在完整玩法迁移和原创彩色像素素材，不在菜单栏图标本身。

原项目是 TypeScript + Vite + PixiJS，另有 Canvas 回退；玩法主要集中在 `src/core`，与渲染结构相对分离。现有鱼类主要用几何形体程序绘制，LCD 是单色网格采样。**已有代码中没有一套可直接复用的 PC FISH 式彩色像素动画资源。** 保留配对、成长、收集节奏，同时重新制作像素画面，比直接沿用现有渲染更符合目标。

## 平台边界

| 需求 | 实现方式 | 边界 |
| --- | --- | --- |
| Mac 菜单栏图标 | SwiftUI MenuBarExtra，像素鱼 template image | 应用运行时显示；退出后消失；系统浅深色优先保证识别 |
| 状态提示 | 图标旁简短数量、展开菜单显示成年/爱心/时间 | 不把完整鱼缸塞进系统菜单栏，避免占满空间 |
| 系统提醒 | UserNotifications 预先安排截止时间 | 主动开启权限，系统负责呈现；不承诺准点打断用户 |
| iPad 后台成长 | 持久化截止时间，恢复时按时间差结算 | 不依靠后台常驻渲染或每秒定时器 |
| 像素画面 | SpriteKit 低分辨率贴图 + nearest 采样 | 原型为 16×10 鱼体；正式鱼种需形态与帧动画规范 |
| 离线单机 | 纯 Swift 状态机 + 本地持久化 | MVP 不需要服务端 |
| 跨设备进度 | 先设计导入/导出，后评估 iCloud | 云同步有冲突合并成本，不能简单让最新文件覆盖 |

Mac 根据用户后续确认，已改为菜单栏常驻 + 无边框 NSPanel，不显示标题栏、红黄绿按钮或 Dock 图标。默认浮在普通应用窗口上方，支持取消置顶、拖动、隐藏/显示和三档整数像素大小。置顶时配置跨 Space 与全屏辅助面板行为；完整全屏兼容性仍需实测，不使用屏保或系统警告层级。

水体使用逐像素 alpha 合成：NSPanel 非不透明、背景 clear，SKView 开启 allowsTransparency，SpriteKit 场景背景 clear，仅水色条带使用可调 alpha。默认不透明度 50%，鱼、造景和底砂保留不透明。调低整个窗口 alpha 会连鱼也变淡，因此透明度只施加到水体节点。iPad 仍用完整游戏界面和不透明水体，不透出其他 App。iPad 不存在与 Mac 对等的第三方系统菜单栏入口。

Apple 原生能力依据：[MenuBarExtra](https://developer.apple.com/documentation/swiftui/menubarextra)、[SpriteView](https://developer.apple.com/documentation/spritekit/spriteview)、[nearest 纹理过滤](https://developer.apple.com/documentation/spritekit/sktexture/filteringmode)、[本地通知](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app)、[后台执行时间限制](https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time)。

## 选型比较

| 路线 | 优点 | 主要成本 | 判断 |
| --- | --- | --- | --- |
| SwiftUI + SpriteKit | 原生菜单栏/通知/触控；Mac 和 iPad 共用核心；像素贴图容易控制 | TypeScript 玩法需要迁移并做一致性对照 | 推荐长期主线 |
| WKWebView + 原生外壳 | 最快保留网页已有玩法 | 仍需新像素渲染，菜单栏状态桥接与网页存档/生命周期处理 | 如优先最快试玩，可作为替代路线 |
| Unity / Godot | 游戏场景和资源工具成熟 | 菜单栏仍需原生集成，增加引擎与发布维护面 | 当前轻量放置玩法没有明显收益 |

不把网页版重构成多端框架，也不在新项目中绑定网页版构建过程。网页版继续独立维护；迁移时用固定版本的规则样本校验 Swift 输出。

## 美术方向

- 以 PC FISH 的彩色、低分辨率、安静陪伴感作方向参考，制作自己的鱼形、场景、图标和界面。
- 海水 `#102D42`、远水 `#173C5B`、海草 `#479C7F`、砂砾 `#EBD49B`、鱼橙 `#FFA24A`、珊瑚 `#D07883`。
- 画面以鱼缸为主体，周围控件保持简洁；方格像素边缘，不用柔光渐变替代像素体积。
- 原型使用系统等宽字，保证中文可读；正式版再评估有明确授权和完整中文字形的像素字体。
- 贴图固定逻辑像素尺寸，nearest 放大，逐步补不同体型和游动、转身、进食动画。

## 推荐阶段

1. **平台验证原型（本次）**：双端工程、彩色像素占位场景、菜单栏、离线计时和通知开关。
2. **养成单机闭环（本次四项玩法已迁移，详见 GAMEPLAY_MIGRATION.md）**：按网页数值迁移星级/品阶、繁育、10 合 1、EXP、背包/图鉴、装饰和存档；用同一 RNG 输入与网页逐项对照。所有旧功能的取舍要明确，不把原型当作已完成移植。
3. **像素美术与体验**：先定 3–5 种不同体型和一个鱼缸的最终效果，再扩充当前网页 29 鱼种与变种；完成键鼠、触控、分屏、小窗口、音频和减少动态效果。
4. **发布准备**：签名、App 图标、通知实际送达、睡眠/唤醒、低系统版本与 iPad 真机、长时间功耗及存档恢复验收；再处理 TestFlight、商店或 Mac 分发。

估算仅供排期：一位熟悉 Swift 的开发者完成单机可玩 MVP 约 2–4 周；完整美术、云同步和商店发布另估。当前未做完整迁移清单与资源验收，不能作为交付承诺。可先用平台原型确认手感和像素方向再细化排期。

## 仍需验证

- iPad 真机横竖屏、分屏/窗口缩放、触控、后台恢复、通知和功耗。
- 最低系统版本尚未运行验证；仅成功编译不能证明这些行为。
