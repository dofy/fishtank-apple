# macOS 候选版交互验收

使用与发行候选相同机器代码及资源的 QA 副本，避免测试繁育、合成、放生和偏好设置影响个人鱼缸。仅修改副本的 Bundle ID、显示名和本地签名；正式产物仍为 `net.yahaha.fishtank.mac`。

## 准备

1. `tools/prepare-mac-validation.sh` 创建 `build/validation/Fishtank-QA.app`，使用独立的 `net.yahaha.fishtank.mac.validation` 沙箱。已存在时用 `--verify-existing` 只检查副本；脚本不会覆盖既有 QA 副本或自动启动应用。
2. 副本的机器代码段、双架构构建 UUID、资源内容与候选逐项核对。可执行文件的签名区会因应用身份改变而改变，不以整个签名后文件的哈希相同作为判据。
3. 解锁 Mac 后，从菜单栏退出个人鱼缸，打开 QA 副本。验收结束退出 QA，再打开 `build/distribution/0.4.0-candidate/Fishtank.app`。

## 操作与通过条件

- [x] 首次启动：只有透明悬浮鱼缸与菜单栏入口，无 Dock 图标、标题栏或红黄绿按钮。初始 3 条鱼、5 颗爱心；菜单栏可打开养成手册。
- [x] 透明与缩放：四档水体 alpha 实测为 0.2/0.4/约 0.7/1.0，鱼和底砂 alpha=1；默认透明水体另有屏幕合成证据。三档尺寸与各自拖动通过。
- [x] 普通窗口置顶与焦点：置顶时显示在原生测试窗口上方；取消后可被其覆盖。拖动后其他测试窗口仍能输入；手册搜索框可以输入。
- [x] 全屏空间：原生测试窗口进入系统独立全屏空间后，置顶鱼缸仍可见，退出全屏后正常。
- [ ] 多个普通桌面空间切换：继续补验，不把独立全屏空间结果扩大为所有桌面组合。
- [x] 窗口生命周期：手册关闭/菜单栏重开、隐藏/显示和移回当前屏幕正常。重启后保留 QA 的位置、大小、透明度和置顶设定。
- [ ] 装饰：拖动海草，左右微调、翻转，重启后位置保留；移动中的造景不会继续吸引停留的小鱼。收回一件初始装饰后放入七彩串灯，夜景与流光开关/速度都生效。
- [x] 繁育：推荐两条初始亲代，确认爱心减 1、背包加 1、出生经验 +5；收下前背景操作不可用。退出重开后子代、出生经验和 3 分钟亲代冷却保留。五分钟成年后再结算 +5，不重复结算。
- [ ] 安全操作：锁定鱼不能放生或选作合成材料；放生/合成需确认。单纯收回有退场动画；放生/合成消耗的鱼立即消失。放生不删除历史图鉴。
- [ ] 声音与减少动态效果：三首曲目、独立开关及音量可辨，隐藏鱼缸且关闭手册后停止。系统减少动态效果开启时，鱼停止位移、串灯不闪动，点击/收回反馈仍可见。
- [ ] 存档：导出 QA JSON；修改 QA 进度后导入，先出现概要预览，取消不替换；确认后恢复所选进度，导入前文件可再恢复。坏 JSON 被拒绝，现有进度保留。
- [ ] 睡眠/唤醒：唤醒后按真实时间结算离线成长与爱心；场景没有补帧狂奔，声音按可见状态恢复。

## 停止自动拖动后的源码排查

发现 `windowDidChangeScreen` 中存在一条主动居中路径：鱼缸暂时不与任何屏幕可用区域相交时，会调用“移回当前屏幕”。[Apple 文档](https://developer.apple.com/documentation/appkit/nswindow/didchangescreennotification) 明确该通知在窗口部分移入或移出屏幕时也会触发，因此不能把它当作显示器断开事件。此路径可能在拖动中改变位置；既有采样没有记录调用栈，不能据此认定它解释了所有跳动。

源码已移除这个窗口切屏回调，改用 `NSApplication.didChangeScreenParametersNotification` 处理显示器配置变化，等待所有鼠标按键释放后再检查窗口是否完全离开可用区域。没有改写 AppKit 的拖动坐标、窗口约束或造景事件分流。SDK `NSWindow.h` 还明确 `performDrag` 会立即返回且不保证向视图发送 mouseUp，因此没有用其返回或视图 mouseUp 冒充拖动结束。

此源码通过独立目录的 Mac arm64/x86_64 Release 构建，日志 `build/validation/cross-screen-static-build.log`，产物在 `build/cross-screen-static/`；没有启动该产物、替换正在运行的候选或操作鼠标。该结果只证明编译通过，跨屏拖动、显示器拔插和用户体验仍待人工验收，发布阻塞项保持未解决。

## 2026-10-21 底部限位改动（待人工验收）

按用户追加要求，在拖动时限制鱼缸底部不能离开桌面，同时允许上下排列的屏幕互相跨入。水面拖动改为保存按下时的窗口框和全局鼠标点，后续由同一抓取点计算位置，使用 AppKit 桌面点、不使用显示器像素倍率。触底后不重置抓取点，回拖时仍按最初的偏移计算；装饰拖动继续交给场景。

边界计算取鼠标所在的竖直通道，将物理边缘相接的上下显示器连成一组。只限制这一组最外侧的可用桌面顶部和底部，内部接缝的菜单栏/Dock 留白不作为拦截边界；另一列较低的显示器不能取消当前显示器露在外面的底部边界。左右位置与画布尺寸不变。仅在水面拖动期间绕过 AppKit 单屏顶部约束，避免它重新拦住内部接缝；松开或隐藏时结束该状态。

10 项几何测试覆盖上下双向穿越、三档画布大小、错位排列、负坐标、外侧 Dock 边界、物理间隙、旁侧较低屏幕、触底后回拖和超高画布的底部优先策略。它们证明几何行为，不替代真实鼠标事件、置顶、输入焦点与装饰拖动回归。此前 no-recenter 版本的人工通过结论不能直接用于这一版的新事件路径。

新的审阅目录为 `build/distribution/0.4.0-review-bottom-bounds/`，隔离副本为 `build/validation/Fishtank-QA-bottom-bounds.app`。准备后不自动启动，不替换个人鱼缸，也不自动拖动。人工需要验证：单屏拖到底部被挡住；上下屏来回可穿越；触底后向上回拖、普通横向跨屏时抓取点稳定；装饰只在缸内移动；拖动不抢其他应用输入焦点。

## 右键晃动鱼缸（macOS）
