## 目标与边界

把“最高星级、最高品阶的两条鱼”升级为按图鉴缺口计算实际成功概率的推荐：

1. 优先最大化单次出生获得未发现普通鱼种的概率。
2. 第一项相同时，最大化单次出生获得未收集的“鱼种 × 品阶”外观的概率。
3. 两项均相同时，优先少消耗高星亲代，再考虑剩余次数、获得时间与稳定 ID。

仅改变推荐对象，不改变出生算法、星级矩阵、品阶权重、鱼种池、爱心消耗、成熟时间、存档格式或随机数序列。推荐不自动繁育，不保证最少次数完成整个图鉴；这是单步最优策略，不是全局资源规划。

## 候选与图鉴历史

候选必须同时满足：未锁定、已成年、tier 为 0 或 uses > 0；两条必须为不同 UUID。展示在鱼缸中的鱼仍可参与。推荐不要求当前爱心足够，因为推荐只选鱼；执行繁育时仍由已有规则校验爱心。

图鉴缺口依据 `discovered` 与 `discoveredVariants` 历史，不能用“当前背包没有”判断缺失。合成、放生后图鉴仍点亮。为兼容旧档，可以把当前持有鱼种/品阶并入内存中的已知集合；已发现鱼种没有任何外观记录时按品阶 1 处理，与网页 `discoveredGradesFor` 一致。不要为推荐写回或改造存档。

初始鱼 tier 0 不是繁育产出目标，不应因为初始鱼外观不全而永远无法“收齐”。隐藏生物不进入普通出生目标。物种名称不影响配对概率，同种、异种亲代均无特殊加成。

## 精确概率

对一对亲代 a、b：

- `T[t] = matrix[minTier+maxTier][t-1] / 100`，t 为 1...5。
- `weights = gradeWeights((Double(a.grade) + Double(b.grade)) / 2)`，必须浮点平均，不能整数除法。
- `G[g] = weights[g-1] / sum(weights)`，品阶权重不是直接的百分比，必须归一化。
- `pool[t]` 为实际出生池；目前每个池中各物种等概率。

```text
P_new_species = Σ_t T[t] × (该池未发现物种数 / 该池总物种数)

P_new_variant = Σ_t Σ_species_in_pool Σ_g
                T[t] × (1 / 该池总物种数) × G[g]
                × I[species:g 尚未点亮]
```

“新外观”概率包含新鱼种的首次外观，并不是“已发现品种的新外观”；两个概率不是互斥事件，不应相加，也不保证和为 100%。如果未来物种抽取改成带权，必须同步使用真实物种权重，不能继续均分。

不要调用真实 breed、随机抽样或 Monte Carlo 来评分。推荐多次调用必须不改变状态和 RNG。评分使用完整 Double，比较误差容忍 `1e-12`，显示时才转百分比并保留一位小数；正数很小时显示“低于 0.1%”，不要误显示成零。

## 选择与性能

使用字典序比较 `(P_new_species, P_new_variant)`，不要做混合加权，否则大量缺失低星外观可能压过一个未发现鱼种，违背优先级。

概率相同时按：

1. 两条亲代 tier 总和更低。
2. 总和相同，最高亲代 tier 更低。
3. 剩余 uses 总和更多。
4. bornAt 总和更早。
5. 排序后的稳定 UUID 字符串字典序。

同 tier、同 grade 的亲代对后代概率影响相同。先按 `(tier, grade)` 分桶，每桶只保留按 uses 多、bornAt 早、稳定 UUID 排序的前两条，允许同一桶内选择两个不同个体。最多 30 桶、60 个代表，避免 20,000 条鱼库存的全量 O(n²) 配对。已知物种和外观集合应预先构建，评分阶段不反复扫描整个库存。

选择完成后的亲代显示顺序可沿用旧 tier/grade/uses/bornAt 排序，不改变选中的集合。

建议纯值返回结构：

```swift
struct BreedRecommendation {
    enum Reason { case newSpecies, newVariant, complete, unreachable, unavailable }
    let parentIDs: [UUID]
    let reason: Reason
    let newSpeciesProbability: Double // 0...1
    let newVariantProbability: Double // 0...1
    let missingSpeciesCount: Int
}
```

## 回退与说明

- 有正的新鱼种概率：显示“优先补新鱼种”及两项概率。
- 新鱼种概率全为 0，但新外观可达：转向“优先补品阶外观”。若仍有未发现鱼种，说明“现有可用亲代暂时无法获得缺失鱼种”。
- 所有普通可繁育鱼种及外观已点亮：返回旧高星/高品阶推荐，说明“普通图鉴已收齐”；隐藏仍需重铸，不应让此状态一直不成立。
- 仍有缺口，但所有有效组合两项概率均为 0：返回旧推荐，并说明“现有可用亲代无法补齐缺失图鉴”，提示等待其他亲代成年或解除锁定；不要伪称图鉴已完成。
- 有效亲代不足两条：返回空数组，显示需要两条未锁定成年亲代，禁用推荐按钮。不要自动解锁鱼。

UI 推荐说明示例：

> 推荐组合（未选用）：优先补新鱼种 · 新鱼种 18.3% · 新外观 18.3%。均为该推荐组合单次繁育的概率，非保底。

只在用户点击推荐按钮/对应快捷键时应用。界面重绘、计时刷新或排序不能覆盖手动选鱼。若界面仍展示推荐概率，必须标明是“推荐组合（已选/未选用）”的概率，不能把它冒充用户另选组合的概率。所有语言和窄屏需避免截断；不在按钮上塞理由、概率或快捷键文字。

## 验收用例

构造测试档时注意：目标缺失鱼种不能又出现在亲代库存中！例如测试缺 prismkoi，要用 astraljelly 作为五星亲代。

| 场景 | 期望 |
| --- | --- |
| 仅缺 prismkoi，普通五星池共 3 种，已有两条可用五星 | 选双五星，新鱼种概率 0.55 / 3 ≈ 18.3% |
| 仅缺 copperband，一星池共 7 种，同时有初始鱼对及双五星 | 选初始鱼，新鱼种概率 1 / 7 ≈ 14.3%，不是双五星 |
| 普通鱼种已齐，仅缺 copperband:1，四条可用一星亲代，两条品阶 1、两条品阶 5，亲代不为 copperband，其他亲代均锁定 | 选两条品阶 1，新外观概率 0.76 × 0.56 / 7 = 6.08% |
| 同时缺一个五星物种和大量一星外观 | 仍优先最大新鱼种概率，不用外观数量加权覆盖 |
| 缺五星物种，但只有初始亲代；还缺可达一星外观 | 推荐补一星外观，提示缺失物种当前不可达 |
| 所有普通物种/外观已齐，隐藏未齐或尚未引入 | complete，沿用高星推荐 |
| 只缺五星，但初始亲代只能出已齐的一星 | unreachable，不能称 complete |
| 亲代锁定、幼年或次数耗尽 | 自动排除；手动锁定亲代繁育仍允许 |
| 已放生/合成的曾获物种 | 不再算新鱼种缺口 |
| 同桶有多个可用个体、输入顺序反转 | 能选同桶两个不同 UUID，概率不变，同分选择稳定 |
| 重复计算推荐/切换排序/界面刷新 | 存档、RNG、爱心、次数不变；手动选择不被覆盖 |

存档加载若会补发缺失的初始鱼，UI 合成夹具应保留三条初始鱼；不希望参与推荐时将其锁定，避免补发的初始鱼改变最优概率。

对若干小型合成库存，用不分桶的穷举算法独立计算所有配对，核对优化结果的两项概率确为字典序最大值。执行 swift test，并按该项目当前约束验证 macOS/iPad 构建与响应式 UI；不要动真实存档、签名设置、安装或发布流程。
